## Why

KbLight раздаётся через GitHub-релизы, но версия программы видна только в свойствах файла: по журналу, присланному с проблемой, не понять, какая версия у пользователя, а сам пользователь не узнает о новом релизе и годами сидит на первой скачанной копии. Пользователь выбрал самый распространённый для таких утилит набор (обсуждение 2026-10-04): версия видна в программе, проверка обновлений включена по умолчанию и выключается флажком, без автоматической установки.

## What Changes

- Версия видна: строка «KbLight <версия>» в окне, строка `KbLight <версия>` в журнале сразу после строки запуска трея, новый ключ `--version` — печатает `KbLight <версия>` в консоль и выходит с кодом 0.
- Проверка обновлений в трее: через минуту после запуска и затем раз в 24 часа, пока трей работает, KbLight спрашивает у GitHub последний релиз `lostintired/sbarda-kblight`. Если он новее — в окне ссылка «доступна версия <N>», одно всплывающее уведомление значка за сеанс работы на каждую новую версию, строка в журнале. Ссылка и уведомление открывают страницу релиза в браузере.
- Ничего не скачивается и не устанавливается само.
- Флажок «Проверять обновления» в окне, по умолчанию включён; хранится в `settings.json` полем `CheckUpdates`. Разовые режимы (`--apply`, `--check`, `--autostart`, `--version`) в сеть не ходят.
- Ошибка сети не мешает ничему: одна строка в журнале до следующей удачной проверки, окно и подсветка работают как раньше.
- **Первое обращение программы в интернет** — в README по-английски и по-русски: что уходит (запрос к `api.github.com` с заголовком `User-Agent: KbLight/<версия>`, ничего больше), как выключить.

## Capabilities

### New Capabilities
- `update-check`: когда и как трей проверяет новый релиз на GitHub, что показывает, как выключается, как переживает ошибки сети.

### Modified Capabilities
- `settings-window`: в составе окна — флажок «Проверять обновления» и строка версии со ссылкой о новой версии.
- `lighting-settings`: в `settings.json` новое поле `CheckUpdates`.
- `diagnostic-log`: строка версии при запуске трея и строки проверки обновлений.
- `command-line`: ключ `--version`.
- `interface-language`: русские и английские тексты версии и проверки обновлений.

## Не входит

- Автоматическое скачивание и установка обновления: неподписанный exe, SmartScreen, замена работающего файла — риск больше пользы.
- Предварительные релизы и черновики: проверяется только последний обычный релиз.
- Номер версии из git-тега при сборке: версия остаётся в `<Version>` в `src/KbLight.csproj` (без NuGet, ADR-005).
- Сборка релиза через GitHub Actions — отдельная задача репозитория, не поведение программы.
- Протокол клавиатуры, запись и чтение блока не меняются — проверки на клавиатуре новыми командами не нужно.

## Impact

- Код: новый `src/UpdateCheck.cs` (запрос, разбор, сравнение версий); `TrayApp.cs` (таймер, уведомление значка, строка журнала); `SettingsForm.cs` (строка версии, ссылка, флажок); `LightSettings.cs` (`CheckUpdates`); `Program.cs` (`--version`); `Text.cs` (новые тексты).
- Сеть: HTTPS к `api.github.com`, только из трея; `HttpClient` из .NET, без NuGet.
- Документы: `README.md`, `README.ru.md` (версия, проверка обновлений, приватность), `docs/ARCHITECTURE.md`, `docs/ADR.md` (ADR-010 — проверка обновлений без автоустановки), `docs/CHANGELOG.md`, `CLAUDE.md` (сценарий проверки).
- Старый `settings.json` без `CheckUpdates` читается как «проверять»; версия 1.1.0 новое поле пропускает.

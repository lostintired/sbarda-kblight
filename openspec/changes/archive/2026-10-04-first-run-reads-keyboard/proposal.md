## Why

Без `settings.json` KbLight берёт значения по умолчанию — «Рябь от нажатий», яркость 100, разноцветный, красный — и при первом же запуске трея принудительно пишет их в клавиатуру. Это настройки автора: у любого другого владельца первый запуск затрёт подсветку, которую он выбрал в sbarda. Перед публичным релизом (ADR-001) первый запуск должен сохранять то, что уже стоит в клавиатуре.

## What Changes

- Пока `settings.json` нет, трей не пишет в клавиатуру по своим поводам (запуск, подключение, сон, «Применить сейчас»). Вместо этого он читает блок настроек, берёт из байтов 8–16 эффект, яркость, скорость, направление, разноцветный режим, номер цвета и цвет, создаёт из них `settings.json` и ничего не пишет.
- Если клавиатуры нет или блок неисправен, `settings.json` не создаётся и в клавиатуру ничего не пишется. Попытка повторяется по обычным правилам: повторы при запуске, подключение клавиатуры, выход из сна.
- Правка в окне до этого момента работает как раньше: сохраняет `settings.json` и пишет выбранное пользователем.
- `--apply` и `--check` без `settings.json` ничего не пишут и завершаются с новым кодом возврата 3 и строкой журнала `--apply: NoSettings — …` или `--check: NoSettings — …`.
- Значения по умолчанию остаются только для двух случаев: показ в окне до первого чтения клавиатуры и нечитаемый `settings.json`.

## Не входит

- Нечитаемый (повреждённый) `settings.json` по-прежнему даёт значения по умолчанию и записывает их. Файл существовал, значит, подсветку уже выбирали, а молча подменять её чтением клавиатуры — отдельное решение.
- Чтение профилей из базы sbarda (`G99_datav2.db`): KbLight не зависит от sbarda.
- Проверка модели клавиатуры (PID) — отдельный change, решение 6 в `docs/HANDOFF.md`.
- Новых команд протокола и новых байтов нет: используется то же чтение `05`, что и сейчас, и те же байты 8–16.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `lighting-settings`: требование «Значения по умолчанию» — при отсутствии файла настройки берутся из клавиатуры, а не из значений по умолчанию.
- `auto-apply`: новое требование «Первый запуск» — пока `settings.json` нет, запросы трея читают клавиатуру вместо записи; «Запись при запуске» ссылается на него.
- `command-line`: требование «Разовая запись» — без `settings.json` ничего не пишется, код возврата 3.

## Impact

- Код: `src/TrayApp.cs` (очередь записи, первый запуск), `src/Keyboard.cs` (чтение блока без записи под мьютексом устройства), `src/LightSettings.cs` (настройки из блока), `src/Program.cs` (код 3).
- Файлы пользователя: `settings.json` появляется только после чтения клавиатуры или правки в окне.
- Протокол: без изменений; байты 10–16 читаются в обратную сторону той же формулой, что пишутся (◐ в `docs/PROTOCOL.md` §4). Пока их смысл не проверен, это безопасно: при первом запуске ничего не пишется, а взятые значения при следующей записи возвращаются в клавиатуру теми же байтами, если они в допустимом диапазоне.
- Нынешний пользователь не затронут: у него `settings.json` есть.
- План проверки на клавиатуре: при закрытом трее переложить `settings.json` пользователя во временное место, выставить в клавиатуре «Спектр» через `python tools/kbtool.py setmode 1 50`, запустить сборку из `publish\` → в журнале `запуск программы: AlreadySet — первый запуск, взял из клавиатуры: effect=1 brightness=50 …`, `kbtool.py read` — по-прежнему «Спектр», в новом `settings.json` — `"Effect": 1`, `"Brightness": 50`. Затем вернуть файл пользователя и выполнить `KbLight.exe --apply`.

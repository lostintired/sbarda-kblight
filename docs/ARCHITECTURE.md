# KbLight — устройство

Что программа обязана делать — `openspec/specs/`; здесь — как она это делает. Протокол клавиатуры — `docs/PROTOCOL.md`, решения — `docs/ADR.md`.

## 1. Назначение

Утилита в трее держит подсветку клавиатуры sbarda такой, какую выбрал пользователь: пишет её в клавиатуру при входе в Windows, при подключении клавиатуры, после сна и при каждой правке. Проверена на ZORNER ZH99 HE (USB `19F5:FB2A`); другие модели подключаются файлами моделей (§7а, ADR-009). Вендорская sbarda.exe этого не делает (ADR-001). Всё, кроме подсветки, — вне проекта (ADR-002).

## 2. Стек и сборка

- C#, .NET 10 (`net10.0-windows`, `win-x64`), WinForms, nullable, implicit usings; NuGet-зависимостей нет (ADR-005).
- HID — P/Invoke: `cfgmgr32` (список интерфейсов), `hid.dll` (размеры отчётов), `kernel32` (`CreateFile`, overlapped `ReadFile` и `WriteFile`).
- `dotnet publish src -c Release -o publish` даёт один `KbLight.exe` (~340 КБ, framework-dependent single-file); нужен .NET Desktop Runtime 10 x64.
- Значок `src/app.ico` собирает `tools/make_icon.py` (Pillow, глиф `U+E765` из Segoe Fluent Icons на градиенте); он же вшит ресурсом `KbLight.app.ico` для трея и окна.
- Масштаб — `PerMonitorV2`; тема — `Application.SetColorMode(SystemColorMode.System)`.

## 4. Потоки

- **Поток окна** — цикл сообщений WinForms: значок, меню, окно настроек, таймеры, скрытое окно `SystemWatcher`. С клавиатурой не общается.
- **Поток записи** — одна задача `Task.Run(Worker)` разбирает очередь (§5); результат возвращается в поток окна через `SynchronizationContext.Post` в `OnApplied`.
- **Сигнал «покажи окно»** — `ThreadPool.RegisterWaitForSingleObject` на событии `Local\KbLight.Show`, дальше `Post(ShowSettings)`.
- `Autostart.IsEnabled()` (вызов `schtasks /Query`) при запуске идёт в `Task.Run`, чтобы не задерживать значок.

## 5. Очередь записи

`RequestApply(force, reason, attempts)` снимает копию настроек и кладёт запрос в `_pending` под блокировкой `_gate`. Свободен поток записи (поднят `_idle`) — он запускается; занят — запрос ждёт, а с уже ждущим объединяется: настройки — новые, `force` — по ИЛИ, попыток — максимум.

Пока `settings.json` нет (`_firstRun`), запрос получает `Adopt = true`: вместо записи поток вызывает `Keyboard.Read()` (сеанс `01` → `05` → `02`, без `06`), а `OnApplied` переносит байты 8–16 в настройки (`LightSettings.SetFromBlock`), сохраняет файл и обновляет окно (`SettingsForm.Reload`). При объединении `Adopt` берётся из нового запроса, так что правка в окне отменяет ожидающее чтение; правка (`FlushEdits`) и успешное чтение снимают `_firstRun`. Пока `_firstRun` стоит, `settings.json` не создаётся.

`Worker` берёт запрос и вызывает `Apply`: до `attempts` вызовов `Keyboard.Apply` (или `Keyboard.Read`) с паузой 2 с после `NotFound` или `Failed`; если тем временем в `_pending` появился запрос, повторы бросаются. Каждая попытка — строка журнала. `OnApplied` обновляет строку состояния (подсказка значка и окно) и сохраняет `LastGoodBlock`, если блок из результата новый.

| Событие | Задержка | `force` | Попыток | Причина в журнале |
|---|---|---|---|---|
| Запуск трея | — | да | 6 | запуск программы |
| `DBT_DEVICEARRIVAL` интерфейса `vid_19f5 … &mi_01` | 1,5 с после последнего | да | 3 | клавиатура подключена |
| `PBT_APMRESUMEAUTOMATIC` или `PBT_APMRESUMESUSPEND` | 3 с после последнего | нет | 3 | выход из сна |
| Правка в окне | 300 мс после последней | да | 1 | изменены настройки |
| Закрытие окна или выход с ожидающей правкой | сразу | да | 1 | изменены настройки |
| «Применить сейчас» | — | да | 1 | вручную |

Почему при запуске и подключении — всегда запись, а после сна — сверка: ADR-006. После «Выхода» `Main` ждёт поток записи до 5 с (`WaitIdle`), чтобы не оборвать сеанс с клавиатурой.

## 6. Запись в клавиатуру: `Keyboard.Apply`

1. Мьютекс `Local\KbLight.Device` — очередь между процессами KbLight (трей и разовые режимы). Ожидание до 10 с; брошенный мьютекс считается взятым; не дождались — работаем без него.
2. Интерфейсы: `CM_Get_Device_Interface_List` по классу HID `{4D1E55B2-F16F-11CF-88CB-001111000030}`, фильтр `vid_19f5` и `&mi_01`.
3. Для каждого интерфейса `ApplyTo`:
   - `CreateFile` на чтение и запись, с общим доступом и `FILE_FLAG_OVERLAPPED`; длины отчётов из `HidP_GetCaps` — 65 и 65;
   - сеанс 1: `01` → `05` → (не `force` и байты 8–16 совпадают — `AlreadySet`) → `06` с прочитанным блоком и новыми байтами 8–16 → 400 мс → `02`;
   - сеанс 2: `01` → `05` → `02`, сверка байтов 8–16 — `Written` или `Failed`.

   Неисправный блок в сеансе 1 (PROTOCOL §4) — запись поверх `LastGoodBlock`, а без него отказ.
4. Итог по интерфейсам: `Failed`, если хоть один `Failed`; иначе `Written`, если хоть один `Written`; иначе первый.

`HidDevice.Command` шлёт отчёт (до 1 с) и читает входные отчёты, пока не придёт `AA <тот же код>` (до 1 с); чужие ответы отбрасывает. Ввод-вывод overlapped: при тайм-ауте — `CancelIoEx` и ожидание конца отменённой операции, и только потом неуправляемые буферы освобождаются.

## 7. Настройки

`%LOCALAPPDATA%\KbLight\settings.json` — `System.Text.Json` с отступами; запись — во временный `.tmp`, затем `File.Move` с заменой.

| Поле | По умолчанию | Что |
|---|---|---|
| `Effect` | 13 | код эффекта (PROTOCOL §5); код не из списка пишется как есть, в окне тогда ничего не выбрано |
| `Brightness` | 100 | 0–100 |
| `Speed` | 0 | 0–4, как ползунок sbarda; в клавиатуру — `4 − Speed` |
| `ReverseDirection` | `false` | байт направления 1 или 0 |
| `Multicolor` | `true` | разноцветный режим |
| `ColorIndex` | 0 | в окне не меняется, пишется как есть |
| `Rgb` | `"#FF0000"` | `#RRGGBB` |
| `LastGoodBlock` | `null` | последний исправный блок, 64 шестнадцатеричных символа |
| `Model` | `null` | `VID:PID` последней клавиатуры, в которую записали или из которой взяли подсветку; по нему окно выбирает список эффектов |

Значения по умолчанию — активный профиль sbarda автора на 2026-10-04 (PROTOCOL §9). В клавиатуру они не пишутся: без файла трей берёт подсветку из клавиатуры (§5), а `--apply` и `--check` завершаются с кодом 3; по умолчанию живут только в окне до первого чтения и при нечитаемом файле. Диапазоны ограничивает `LightState.From`.

## 7а. Модели клавиатур

`KeyboardModels.Current()` — встроенные модели (ресурсы `KbLight.models.*`), затем `%LOCALAPPDATA%\KbLight\models\*.json` по имени файла; свой файл с тем же `VID:PID` заменяет встроенный, из двух своих берётся первый. Свои файлы кешируются по пути, времени изменения и длине и перечитываются только изменившиеся; строки журнала о файле (`не прочитан`, `заменяет встроенное описание`) — один раз на содержимое. Вызывается перед каждым обменом (под мьютексом устройства) и при открытии окна, кеш — под `lock`.

Обмен (`Keyboard.ForEachInterface`): путь интерфейса разбирается на `vid`, `pid`, `mi`. Совпал с моделью — интерфейс получает запись или чтение, результат помечается моделью (`ApplyResult.Model`). `vid_19f5` без модели для его `VID:PID` — PID в набор незнакомых, интерфейс не открывается. Знакомых нет, незнакомые есть — `Unsupported` с наименьшим PID (`ApplyResult.UnknownId`); есть и те и другие — строка журнала «пропускаю» на каждый незнакомый PID.

`OnApplied` после `Written`/`AlreadySet` пишет `VID:PID` модели в `Model`; сменился — сохраняет файл и вызывает `SettingsForm.Reload` (строка «Клавиатура», список эффектов).

Сборка `-p:NoBuiltinModels=true` не встраивает `src/models/*.json` — для ручной проверки `Unsupported` на единственной клавиатуре.

## 8. Окно

`SettingsForm` правит тот же объект `LightSettings`, что и трей, и после каждой правки поднимает `SettingsChanged`; дальше таймер 300 мс и `FlushEdits` (сохранить и записать). Доступность элементов — по `EffectOptions` эффекта (PROTOCOL §5): яркость — `0x01`, скорость — `0x02`, «Разноцветный» — `0x20`, цвет — `0x10` при выключенном разноцветном режиме, «Обратное направление» — любой из `0x04`, `0x08`, `0x40`, `0x80`. Размер — `AutoSize`, масштаб — `AutoScaleMode.Dpi`; в тёмной теме у ссылки «Журнал» свой цвет `#60CDFF`.

## 10. Автозапуск

`schtasks /Create /TN KbLight /XML <файл> /F` с XML задачи: `LogonTrigger` текущего пользователя (`DOMAIN\user`), `InteractiveToken`, `LeastPrivilege`, действие `<exe> --tray`, `MultipleInstancesPolicy` — `IgnoreNew`, без условий батареи, `ExecutionTimeLimit` — `PT0S`, приоритет 4. XML пишется в `%TEMP%\kblight-task-<pid>.xml` (UTF-16) и сразу удаляется; текст в нём только ASCII, потому что `schtasks` выводит XML в кодировке консоли. Выключение — `schtasks /Delete /TN KbLight /F`, проверка — код возврата `schtasks /Query /TN KbLight`. Почему не ключ `Run` — ADR-004.

## 11. Журнал

`Log.Write` в `AppFiles.cs`: строка `yyyy-MM-dd HH:mm:ss.fff  сообщение`, `File.AppendAllText` под блокировкой внутри процесса; файл больше 512 КБ переименовывается в `kblight.log.old`. Ошибки ввода-вывода журнала глотаются.

## 11а. Язык

`Text.Ru` вычисляется один раз при первом обращении: `KBLIGHT_LANG` (`ru`/`en`, без учёта регистра), иначе `CultureInfo.CurrentUICulture` — на Windows это язык интерфейса пользователя, а не региональные форматы; `ru` — русский, всё остальное — английский. Каждый текст — свойство или метод `Text` с парой строк; `.resx` и сателлитные сборки не используются (два языка, сверка со спекой `interface-language` по одному файлу). Не переводятся статусы, состояние `effect=…`, ключи, коды выхода, названия из файлов моделей и сообщения исключений Windows и .NET. Встроенные модели разбираются один раз, названия их эффектов берутся на языке процесса.

## 11б. Версия и проверка обновлений

`AppVersion.Current` — `Assembly.GetName().Version`, три числа, то есть `<Version>` из csproj без хвоста `+sha`. Трей пишет `KbLight <версия>` в журнал после строки запуска; окно показывает её под строкой состояния; `--version` печатает её: `AttachConsole(ATTACH_PARENT_PROCESS)` только если стандартный вывод не перенаправлен (иначе подключение к консоли заменило бы перенаправленный дескриптор), затем запись в `Console.OpenStandardOutput()`.

Проверка (spec `update-check`, ADR-010): таймер WinForms `_updateTimer` — 60 с после запуска, дальше 24 ч; тик запускает `UpdateCheck.FindNewer` в `Task.Run`, итог возвращается в поток окна через `SynchronizationContext.Post`, как итог записи. `HttpClient` статический, тайм-аут 15 с, `User-Agent: KbLight/<версия>`; разбор `tag_name` и `html_url` через `JsonDocument`; `html_url` принимается только с префиксом страницы репозитория. Найденная версия — ссылка в окне (`SettingsForm.SetUpdate`), `ShowBalloonTip` и строка журнала; номер показанной версии хранится в поле трея, повтор той же версии молчит. Ошибка пишется в журнал один раз до удачной проверки. Флажок окна поднимает `UpdatesToggled` (не `SettingsChanged`): сохраняет `settings.json` без записи в клавиатуру, при первом запуске — только в памяти.

## 13. Состояние проверки: 2026-10-04, версия 1.2.0

Проверено на клавиатуре и в системе:

- `--check` при совпадении — `AlreadySet`, код 0; после подмены эффекта через `kbtool.py setmode 1` — `Written`, эффект снова 13; `--apply` — `Written`;
- запуск трея — запись через 0,4 с после старта; запуск задачей `schtasks /Run /TN KbLight` — процесс с `--tray` и запись при старте;

Не проверено:
- всплывающее уведомление о новой версии глазами и щелчок по нему (код тот же, что пишет строку журнала);

- настоящий вход после перезагрузки, выход из сна, запись (а не чтение) при переподключении — нужно руками;
- скорость, направление, номер цвета, цвет и выключенный разноцветный режим: байты 10–16 пишутся по разбору sbarda.exe, а менялись пока только эффект и яркость;
- что клавиатура показывает: глазами проверены только эффекты 1 и 6 и яркость 50.

## 14. Ограничения

- До входа пользователя, на экране блокировки, подсветку не ставим: задача стартует при входе. Для этого нужна задача «при запуске системы» с правами администратора.
- Эффекты 0 (своя подсветка клавиш) и 128 (музыка) не поддерживаются (ADR-007).
- Путь к exe записан в задаче: после переноса exe автозапуск включают заново.
- Флажок автозапуска узнаёт состояние задачи только при запуске программы.
- PID клавиатуры не проверяется; формат блока подтверждён только на `FB2A` с прошивкой от 1 августа 2025.

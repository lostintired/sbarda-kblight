# ADR — решения KbLight

Почему программа устроена так, а не иначе. Что она делает — `openspec/specs/`, как — `docs/ARCHITECTURE.md`. Новое решение — следующий номер; отменённое не удаляется, а помечается ссылкой на то, что его заменило.

## ADR-001. Своя программа вместо sbarda.exe — 2026-10-04

**Контекст.** После перезагрузки клавиатура светилась не тем эффектом, что выбран в sbarda. Автозапуск sbarda не работал: в `HKCU\…\Run` стояло `…\sbarda\G68 Ultra.exe -autorun`, а такого файла нет — строка зашита в sbarda.exe. Но и запущенная sbarda.exe подсветку не возвращает: при старте она только читает клавиатуру, команды записи нет (PROTOCOL §6), а опыт «поставить "Спектр" и запустить sbarda» оставил «Спектр».

**Решение.** Своя утилита, которая сама пишет подсветку в клавиатуру. Битую запись автозапуска sbarda удалили.

**Последствия.** Подсветку меняют только в KbLight: правку в sbarda KbLight перезапишет при следующей записи. sbarda.exe остаётся установленной для остальных настроек клавиатуры.

## ADR-002. Только подсветка — 2026-10-04

**Контекст.** sbarda настраивает раскладку, макросы, срабатывание и Rapid Trigger, мёртвые зоны, частоту опроса. Жалоба была только на подсветку, а раскладку и прочее sbarda при каждом запуске читает из клавиатуры — значит, клавиатура хранит их сама.

**Решение.** KbLight меняет только байты подсветки 8–16 блока настроек. Раскладки, макросы, срабатывание — вне проекта.

**Последствия.** Остальное по-прежнему настраивается в sbarda.exe; подсветку при этом в ней не трогают (ADR-001).

## ADR-003. Запись через чтение блока и сверку — 2026-10-04

**Контекст.** Подсветка лежит в одном 32-байтном блоке с другими настройками; что значат байты 0–7 и 17–31, неизвестно (PROTOCOL §4). Блок, собранный с нуля, мог бы сбить эти настройки.

**Решение.** Как в sbarda.exe: прочитать блок, заменить байты 8–16, записать; затем отдельным сеансом перечитать и сверить. Неисправный ответ — запись поверх последнего исправного блока (`LastGoodBlock`), а если его нет — отказ.

**Последствия.** Запись — два сеанса, около полсекунды; «уже стоит» определяется без записи; чужие байты блока уходят такими, какими пришли.

## ADR-004. Автозапуск — задача планировщика, а не ключ Run — 2026-10-04

**Контекст.** Программы из `Run` Windows запускает с задержкой после входа и может тихо отключить через `StartupApproved`; запись sbarda там и была битой. Прав администратора у программы нет и не нужно.

**Решение.** Задача планировщика `KbLight` на вход текущего пользователя, с обычными правами, действие `<exe> --tray`; создаётся через `schtasks /Create /XML` без повышения прав.

**Последствия.** Старт сразу при входе; задача видна в «Планировщике заданий». Путь к exe записан в задаче — после переноса exe автозапуск включают заново.

## ADR-005. .NET 10 WinForms без зависимостей — 2026-10-04

**Контекст.** Нужны значок в трее, маленькое окно и обмен с HID-устройством; на компьютере есть .NET 10 SDK и Desktop Runtime.

**Решение.** WinForms на .NET 10, HID через P/Invoke, без NuGet-пакетов; поставка — один framework-dependent exe около 340 КБ.

**Последствия.** Нужен .NET Desktop Runtime 10 x64. Установщика нет — exe копируется в `%LOCALAPPDATA%\Programs\KbLight`.

## ADR-006. Когда писать, а когда только сверять — 2026-10-04

**Контекст.** Неизвестно, совпадает ли то, что клавиатура отдаёт в блоке сразу после включения питания, с тем, что она показывает. Во сне USB может остаться под питанием, а может и сбросить устройство.

**Решение.** При запуске трея, при подключении клавиатуры, после правки и по команде — запись всегда (`force`). После сна — сверка и запись только при расхождении; если клавиатура при выходе из сна определилась заново, срабатывает и запись при подключении. Попыток: при запуске до 6, при подключении и после сна до 3, с паузой 2 с.

**Последствия.** Лишняя запись при каждом входе, около полсекунды. Первая строка журнала после перезагрузки покажет, что клавиатура хранит после включения, — по ней решение можно пересмотреть.

**Проверка, 2026-10-04.** После переподключения кабеля клавиатура отдала и показала «Волну», а не записанный перед этим «Спектр» (PROTOCOL §4): записанное `06` питание не переживает. Запись при подключении нужна; сверка вместо неё дала бы то же, что и запись, — блок отличается.

## ADR-007. Без музыкального режима и своей подсветки клавиш — 2026-10-04

**Контекст.** Эффект 128 (Musical Rhythm) — подсветка под звук компьютера; судя по устройству sbarda, её ведёт сама программа (не проверялось). Эффекту 0 (Custom Light) нужны цвета каждой клавиши, а команда для их загрузки не расшифрована (PROTOCOL §7).

**Решение.** В списке эффектов KbLight их нет.

**Последствия.** Если выбрать их в sbarda, KbLight при следующей записи вернёт свой эффект. Добавлять — отдельным change после расшифровки протокола.

## ADR-008. Свои настройки, а не база sbarda — 2026-10-04

**Контекст.** sbarda хранит профили в SQLite `%LOCALAPPDATA%\sbarda Files\db\G99_datav2.db`. Читать её — зависеть от формата чужой программы и её версий.

**Решение.** У KbLight свой `settings.json`; значения по умолчанию один раз взяты из активного профиля sbarda: эффект 13, яркость 100, скорость 0, разноцветный, красный.

**Последствия.** Правки в sbarda в KbLight не попадают, и наоборот.

## ADR-009. Модели клавиатур — файлы данных — 2026-10-04

**Контекст.** KbLight писал в любую клавиатуру `VID 19F5` с интерфейсом `MI_01`, а проверен только на ZORNER ZH99 HE (`19F5:FB2A`). У производителя есть и другие PID, и список эффектов у них может отличаться. Проект публичный: владелец другой модели должен суметь подключить её сам, без пересборки, и не рисковать, пока не проверил.

**Решение.** Модель — JSON-файл: название, `VID:PID`, интерфейс, эффекты с параметрами. Встроенные лежат в `src/models/` и вшиваются в exe; свои — в `%LOCALAPPDATA%\KbLight\models\`, свой файл с тем же `VID:PID` заменяет встроенный. KbLight открывает только интерфейсы известных моделей; клавиатура `19F5` без файла не получает ни одной команды, итог — `Unsupported`, код 4. Протокол (команды, блок, байты 8–16) в файле не настраивается: у всех моделей его собирает одна функция sbarda.exe. Файл собирается из базы sbarda (`tools/make_model.py`), порядок — `docs/ADDING-A-KEYBOARD.md`.

**Последствия.** Новая модель — без изменения кода: файл в папку, а после проверки — PR в `src/models/`. Неверный код эффекта в своём файле покажет на клавиатуре не то, что в списке; поэтому документ требует проверить каждый код через `kbtool.py setmode`. Модель с другим протоколом потребует отдельного change.

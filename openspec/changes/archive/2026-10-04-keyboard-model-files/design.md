## Context

Сейчас модель зашита в код в двух местах:
- `Keyboard.IsLightingInterface` принимает любой путь с `vid_19f5` и `&mi_01`, им же пользуется `SystemWatcher`;
- `Effect.All` в `src/LightSettings.cs` — 20 эффектов ZH99 HE с масками `EffectOptions`.

Окно (`SettingsForm`) строит список из `Effect.All`, `LightSettings.Describe` берёт оттуда название. Протокол (`01`/`02`/`05`/`06`, байты 8–16) от модели не зависит: sbarda.exe собирает блок одной функцией для всех PID (PROTOCOL §8).

## Goals / Non-Goals

**Goals:**
- Модель — данные, а не код: встроенная ZH99 HE и свои файлы читаются одним кодом и в одном формате.
- Незнакомая клавиатура `19F5` не получает ни одной команды.
- Владелец другой модели собирает файл из своей базы sbarda одной командой и проверяет его без пересборки.

**Non-Goals:**
- Параметры протокола в файле модели (смещения, команды, длина блока).
- Свои настройки для каждой из нескольких клавиатур.

## Decisions

1. **Формат файла и встроенная модель.** Файл — JSON из `keyboard-models` («Файл модели»). Встроенная ZH99 HE лежит в `src/models/zorner-zh99-he.json` и попадает в exe как `EmbeddedResource`. Тот же файл служит образцом для PR и для `docs/ADDING-A-KEYBOARD.md`.
   - Параметры — строки (`"brightness"`), а не число `config_func`: файл пишут руками, и опечатку в слове видно в журнале.
   - Перевод из `config_func` делает `tools/make_model.py`.

2. **Названия эффектов.** Во встроенном файле названий нет, только `id` и `options`. Названия по коду остаются таблицей в коде (`Effect.KnownNames`): следующий change переведёт её, не трогая файлы моделей. `name` в файле нужен для кодов, которых в таблице нет, и перекрывает таблицу.

3. **`KeyboardModels`** (новый `src/KeyboardModel.cs`):
   - `record KeyboardModel(string Name, ushort Vid, ushort Pid, byte Interface, IReadOnlyList<Effect> Effects, string? File)`;
   - статический `Current()` возвращает список моделей: встроенная, затем файлы `models\*.json` по имени, с заменой по `VID:PID`;
   - разобранные файлы кешируются по (путь, время изменения, длина): файл перечитывается и о нём пишется в журнал, только если он изменился (требование «строка один раз на каждое содержимое»);
   - вызывается из потока записи и из потока окна, поэтому кеш под `lock`;
   - разбор — `System.Text.Json` с `PropertyNameCaseInsensitive`; проверка полей — вручную, с текстом причины по-русски для журнала: «нет поля name», «pid должен быть четырьмя шестнадцатеричными цифрами», «неизвестный параметр <слово>», «эффект <код> повторяется», «список effects пуст».

4. **Выбор интерфейсов.** `Keyboard.ForEachInterface` разбирает путь регуляркой `vid_([0-9a-f]{4})&pid_([0-9a-f]{4})(?:&mi_([0-9a-f]{2}))?`:
   - путь совпадает с моделью по VID, PID и `mi` — интерфейс получает действие (запись или чтение);
   - путь с `vid_19f5`, а модели для его `VID:PID` нет, — PID попадает в набор незнакомых. Интерфейс не открывается;
   - если знакомых интерфейсов нет, а набор незнакомых не пуст, итог — `Unsupported` с первым PID по возрастанию. Если есть и знакомые, по каждому незнакомому PID пишется строка «пропускаю».
   
   `ApplyStatus` получает значение `Unsupported`, `ApplyResult` — поле `Model` (модель, с которой получен итог). Повторы в `TrayApp.Apply` и так идут только после `NotFound` и `Failed`, так что `Unsupported` повторов не даёт.

5. **Событие подключения.** `SystemWatcher` вызывает `Keyboard.IsInteresting(path)`: путь содержит `vid_19f5` или подходит к одной из моделей. Незнакомая клавиатура тоже вызывает запись, чтобы появилось состояние `Unsupported`.

6. **`Model` в настройках.**
   - `OnApplied` после `Written` или `AlreadySet` с `result.Model` записывает `VID:PID` в `_settings.Model`. Если значение сменилось, файл сохраняется (кроме первого запуска до чтения), а открытое окно получает `ModelChanged`: перестраивает список эффектов и строку «Клавиатура».
   - Окно ищет модель по `_settings.Model` через `KeyboardModels.Current()`; не нашло — список из встроенной, строка «не определена».
   - Поле `Model` старые версии пропускают: `System.Text.Json` по умолчанию игнорирует незнакомые поля. Формат остаётся совместимым, поэтому это минорная версия.

7. **Окно.**
   - Строка «Клавиатура: …» — `Label` над списком «Эффект».
   - Ссылка «Модели» — `LinkLabel` рядом с «Журналом»: `Directory.CreateDirectory`, затем `explorer.exe "<папка>"`.
   - Список «Эффект» строится из эффектов модели при открытии окна и по `ModelChanged`.

8. **Код 4** — в `Program.ApplyOnce` новая ветка `Unsupported => 4`.

9. **Инструменты.**
   - `tools/make_model.py --name "<название>" [--pid XXXX] [--db <путь>] [--out <файл>]`:
     - PID берёт у единственной подключённой `19F5` (через функции `kbtool.py`), а если клавиатур несколько — требует `--pid`;
     - `interface` — номер `mi` интерфейса с отчётами 65/65;
     - эффекты — строки `t_light_data` активного профиля (`t_profile_data.status = 1`) в порядке `mode`, без `config_func` с битами `0x100` и `0x200` и без `mode = 255`;
     - `config_func` переводит в `options` по таблице PROTOCOL §5;
     - по умолчанию пишет в `%LOCALAPPDATA%\KbLight\models\<vid>-<pid>.json`.
   - `tools/kbtool.py --pid XXXX <команда>` — работать только с этой моделью; без ключа — как сейчас, первая `19F5` с отчётами 65/65.

10. **Проверка `Unsupported` без второй клавиатуры.** В `src/KbLight.csproj` встроенный файл подключается при условии `'$(NoBuiltinModels)' != 'true'`. Сборка `dotnet publish src -c Release -o publish-test -p:NoBuiltinModels=true` даёт exe, для которого ZH99 HE незнакома. Это крючок только для ручной проверки; в релизную сборку он не попадает.

11. **`docs/ADDING-A-KEYBOARD.md` — по-английски.** Его читают владельцы других моделей со всего мира. Из `README.md` и `README.ru.md` на него ведут ссылки.

## Risks / Trade-offs

- Неверный код эффекта в своём файле → клавиатура покажет не то, что в списке. Поэтому документ требует сначала проверить каждый код через `kbtool.py setmode`, а журнал показывает, какой файл модели взят.
- Другая модель с тем же протоколом, но другим смыслом байтов 10–16 → цвет или скорость будут не те. Протокол общий, так его собирает sbarda.exe; если найдётся модель с отличиями, это повод для change с параметрами протокола.
- Свой файл заменяет встроенную ZH99 HE целиком → можно случайно сузить список. В журнале всегда есть строка о замене; удалить файл — значит вернуть встроенное описание.
- Файлы перечитываются перед каждым обменом → несколько `stat` на запись. При обмене около 0,5 с это незаметно.

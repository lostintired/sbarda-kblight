## Context

- `LightState` (`src/Keyboard.cs`) — это 9 байт подсветки. `WriteTo` кладёт их в блок по смещению 8, `Matches` сверяет те же 9 байт, `Describe(block)` печатает состояние для журнала. Модель в запись не попадает: `ForEachInterface` знает её, но передаёт действию только путь, а `ApplyResult.Model` дописывает уже после.
- `LightSettings` — плоский класс, а `Clone()` — `MemberwiseClone`. Его снимок уходит в очередь записи трея (`ApplyRequest.Settings`) и не должен меняться под потоком записи.
- Первый запуск: `TrayApp.OnApplied` при `adopted` вызывает `SetFromBlock(block)`, ставит `Model` и сохраняет файл. Блок есть в каждом удачном `ApplyResult` (`AlreadySet`, `Written`), а при `Failed` после записи там прочитанный блок до неё.
- Окно — одна `TableLayoutPanel` из трёх колонок. `UpdateControls` включает и выключает элементы по `EffectOptions` выбранного эффекта.
- Что значит каждый байт 24–31 — `docs/PROTOCOL.md`, §4. Требования — в спеках этого изменения.

## Goals / Non-Goals

**Goals:**
- Light box живёт в той же записи, что основная подсветка: один сеанс, одна сверка, одна строка журнала. Отдельного прохода к клавиатуре нет.
- Если модель без light box или в `settings.json` нет `LightBox`, в клавиатуру уходят те же байты, что у версии 1.2.0.

**Non-Goals:**
- Режимы light box в файле модели: набор режимов известен только для ZH99 HE, поэтому он задаётся в коде. Если у другой модели он окажется иным, это отдельное изменение.
- Отдельная кнопка «применить light box», отдельная очередь, отдельные поводы записи.

## Decisions

1. **`LightBoxSettings` — неизменяемый `record`**, свойство `LightSettings.LightBox` типа `LightBoxSettings?`. `MemberwiseClone` копирует ссылку, а для неизменяемой записи это безопасно: окно меняет light box через `with` и присваивает новый объект. Поэтому снимок в очереди остаётся прежним. Поля — `Mode`, `Brightness`, `Speed`, `Multicolor`, `Rgb`, как в спеке; `System.Text.Json` сериализует `record` с `init` без настроек.
   - Альтернатива — изменяемый класс и глубокий `Clone()`. Это ещё одно место, которое легко забыть при следующем поле.

2. **`LightState` получает необязательную часть light box.** `LightState.From(settings, model)`: если `model.LightBox` и `settings.LightBox` не `null`, в состоянии лежат 7 байт light box (24–26, 28–31). Иначе часть пуста, а `WriteTo` и `Matches` работают только с 8–16. Байт 28 вычисляется уже здесь, по таблице режимов (`LightBoxMode.HasMulticolor`): поэтому сверка и запись видят одно и то же значение. Байт 27 `WriteTo` не трогает.
   - `Describe(block, model)` дописывает ` | box …`, если у модели есть light box, независимо от настроек. Так журнал показывает, что лежит в клавиатуре, ещё до того, как light box взят.

3. **Состояние строится для каждой модели в `Keyboard`.** Сейчас `Apply` принимает готовый `LightState`. Теперь он принимает `LightSettings`, а `ForEachInterface` передаёт действию `(path, model)`. `ApplyTo` вызывает `LightState.From(settings, model)` для своей клавиатуры. Две разные модели в одной записи получат каждая свои байты. `TrayApp.Apply` и `Program.ApplyOnce` передают настройки вместо `LightState`.
   - Альтернатива — строить состояние у вызывающего по `settings.Model`. Это ломается, когда подключена клавиатура другой модели, чем записана в `Model`.

4. **Таблица режимов в коде.** `LightBoxMode(int Id, EffectOptions Options)`, пять строк по спеке «Режимы light box». Флаги берутся из существующего `EffectOptions` (`Brightness`, `Speed`, `Color`, `Multicolor`), и поэтому окно включает элементы группы тем же кодом, что элементы основной подсветки. Названия — `Text.LightBoxModeName(id)`.

5. **Взять light box из клавиатуры — в `TrayApp.OnApplied`.** После результата с блоком (`AlreadySet` или `Written`), если `_settings.LightBox is null`, у `result.Model` есть light box и первый запуск закончен (или этот результат его закончил), трей вызывает `LightBoxSettings.FromBlock(block)`, сохраняет файл и вызывает `_form?.Reload()`. Это то же место, где берётся `Model`. Пока `LightBox` нет, запись light box не трогает (решение 2), поэтому байты, из которых он взят, остались ровно такими, какими были.
   - Первый запуск (`adopted`) делает то же внутри `SetFromBlock`, чтобы всё легло одним сохранением.
   - Разовые режимы `Program.ApplyOnce` light box не берут: `settings.json` у них только для чтения, кроме `LastGoodBlock`, которого они тоже не меняют.

6. **Окно.** После строки «Обратное направление» идёт строка-заголовок «Light box» (жирная `Label` с верхним отступом) и четыре строки в той же сетке: «Режим» (`ComboBox` из таблицы режимов), «Яркость», «Скорость», «Цвет» + «Разноцветный». Это отдельные элементы, но строки добавляет тот же `AddRow`. Видимость строк задаёт `KeyboardModels.Find(_settings.Model)?.LightBox`. Пока `LightBox` нет, показываются значения по умолчанию из спеки, и первая правка создаёт `LightBox` целиком.
   - `GroupBox` вместо заголовка — отдельная раскладка внутри рамки, и ширина подписей расходится с верхней частью окна.

7. **ADR-003 дополняется**, а не заменяется: «KbLight меняет байты 8–16 и, у моделей с light box, 24–26 и 28–31; остальные уходят как прочитаны». Причина — опыт 2026-10-06 из `docs/PROTOCOL.md`.

## Risks / Trade-offs

- [Клавиши Fn меняют light box, а после сна KbLight возвращает своё] → Так же устроена основная подсветка (proposal, «Не входит»). В README появится строка: менять light box надёжнее в окне.
- [Другая прошивка ZH99 HE держит в 24–31 что-то иное] → Пишем только при `"lightBox": true`, после записи перечитываем и сверяем. Расхождение даёт `Failed`, и запись повторяется не бесконечно. Свой файл модели с `"lightBox": false` выключает функцию.
- [Окно стало выше] → Пять строк, около 160 px при 96 dpi. Окно и так подстраивается под содержимое (`AutoSize`).
- [Байт 25 > 100 из клавиатуры] → При взятии ограничивается 100, в журнале печатается как есть.

## Migration Plan

- Файл 1.2.0 без `LightBox` читается и при первом чтении клавиатуры дополняется ею (решение 5). Подсветка в клавиатуре не меняется.
- Откат на 1.2.0: поле `LightBox` пропускается, байты 24–31 1.2.0 не трогает. Light box остаётся тем, что записал 1.3.0, до отключения питания.

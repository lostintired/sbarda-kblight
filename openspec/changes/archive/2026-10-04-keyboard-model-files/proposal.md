## Why

KbLight пишет в любую клавиатуру с `VID 19F5` и интерфейсом `MI_01`, а проверен только на ZORNER ZH99 HE (`19F5:FB2A`). У производителя есть и другие PID (`FB29`, `FCE0`, `FE20`, `FE50`, `FF0C`, `FF1D`, PROTOCOL §1), и список эффектов у них может быть другим. В публичном релизе программа не должна вслепую писать в непроверенную модель. При этом владелец другой модели должен суметь добавить её сам, без пересборки, и поделиться описанием с остальными.

## What Changes

- **Файл модели** — JSON с названием, `VID:PID`, номером интерфейса и списком эффектов. Для каждого эффекта указаны код, параметры и, по желанию, название. Описание ZORNER ZH99 HE встроено в exe. Свои файлы кладутся в `%LOCALAPPDATA%\KbLight\models\` и читаются без перезапуска. Свой файл с тем же `VID:PID` заменяет встроенный.
- **Запись только в известные модели.** KbLight открывает только интерфейсы, для которых есть файл модели. Если найдена клавиатура `VID 19F5`, для которой файла нет, KbLight ничего в неё не пишет. Итог — новый статус `Unsupported`: строка в журнале, состояние в подсказке значка и в окне, код возврата 4 у `--apply` и `--check`.
- **Эффекты в окне — из файла модели.** Список и параметры эффектов берутся из файла подключённой модели, а без клавиатуры — из последней найденной. `settings.json` получает поле `Model` (`"19F5:FB2A"`); прежние версии это поле игнорируют.
- **Окно.** Новая строка «Клавиатура: <название>» и ссылка «Модели» рядом с «Журналом». Ссылка открывает папку `models`, создав её при необходимости.
- **Инструменты для владельцев других моделей:**
  - `tools/make_model.py` собирает файл модели из базы sbarda (`t_light_data`: `mode`, `config_func`) и `VID:PID` подключённой клавиатуры;
  - в `tools/kbtool.py` добавляется ключ `--pid`, чтобы работать с конкретной моделью.
- **Документ `docs/ADDING-A-KEYBOARD.md` (по-английски).** Как узнать `VID:PID`, проверить блок через `kbtool.py read` и `setmode`, собрать файл, положить его в папку и прислать в репозиторий через PR или issue. Встроенные модели лежат в `src/models/`.

## Не входит

- Другие протоколы. Команды `01`/`02`/`05`/`06`, блок 32 байта и байты 8–16 у всех моделей одинаковы: так их собирает sbarda.exe, и в файле модели они не настраиваются. Модель с другим протоколом — отдельный change.
- Свои настройки подсветки для каждой из нескольких одновременно подключённых клавиатур: все получают одни и те же настройки, как сейчас.
- Наборы настроек подсветки, которые можно переключать (профили sbarda). Отдельная возможность, если её попросят.
- Перевод интерфейса — следующий change. Название эффекта в файле модели — одна строка, без перевода.
- Загрузка файлов моделей из интернета.

## Capabilities

### New Capabilities

- `keyboard-models`: файлы моделей — формат, где лежат, встроенная ZH99 HE, порядок замены, ошибки в файлах, что происходит с незнакомой клавиатурой `VID 19F5`.

### Modified Capabilities

- `keyboard-write`: «Только вендорский интерфейс клавиатуры» — открываются только интерфейсы известных моделей, новый статус `Unsupported`.
- `lighting-settings`:
  - «Файл настроек» — новое поле `Model`;
  - «Список эффектов» и «Параметры эффектов» — список и параметры берутся из файла модели, а прежний список становится содержимым встроенной ZH99 HE.
- `auto-apply`:
  - «Запись при подключении клавиатуры» — срабатывает на интерфейсы известных моделей и на любой `vid_19f5`;
  - «Состояние в подсказке значка и в окне» — текст для `Unsupported`;
  - повторов при `Unsupported` нет.
- `command-line`: «Разовая запись» — код возврата 4.
- `settings-window`:
  - «Состав окна» — строка «Клавиатура: …» и ссылка «Модели»;
  - новое требование «Папка моделей из окна».
- `diagnostic-log`: «Что попадает в журнал» — статус `Unsupported` и строки о файлах моделей.

## Impact

- **Код:**
  - `src/Keyboard.cs` — выбор интерфейсов по моделям, `Unsupported`;
  - новый `src/KeyboardModel.cs` — чтение и проверка файлов;
  - `src/LightSettings.cs` — встроенный список уходит в `src/models/zorner-zh99-he.json`, ресурс exe;
  - `src/SystemWatcher.cs` — фильтр события подключения;
  - `src/TrayApp.cs`, `src/SettingsForm.cs`, `src/Program.cs`.
- **Инструменты:** `tools/kbtool.py` (`--pid`), новый `tools/make_model.py`; оба только на стандартной библиотеке Python.
- **Файлы пользователя:** папка `%LOCALAPPDATA%\KbLight\models\`, поле `Model` в `settings.json`. У нынешнего пользователя ничего не меняется: ZH99 HE встроена.
- **Протокол:** без новых команд и байтов. План проверки на клавиатуре:
  - `--check` с встроенным описанием — `AlreadySet`, как раньше;
  - свой файл `19F5:FB2A` с тремя эффектами и названием «Тест» — окно показывает «Клавиатура: Тест» и три эффекта, в журнале строка о замене встроенного описания;
  - файл с ошибкой — строка журнала, файл пропущен;
  - временная сборка без встроенного описания — `Unsupported`, код 4, `kbtool.py read` показывает, что блок не изменился;
  - после всего — `KbLight.exe --apply`.

## Context

Версия задаётся `<Version>` в `src/KbLight.csproj` и попадает в сборку; `Application.ProductVersion` отдаёт `1.1.0+<sha коммита>`. Программа до сих пор не ходила в сеть; NuGet не используется (ADR-005), но `System.Net.Http` и `System.Text.Json` есть в самом .NET. Трей уже держит `NotifyIcon`, таймеры WinForms и очередь записи в клавиатуру; поток окна устройство не ждёт.

## Goals / Non-Goals

**Goals:**
- Одна точка правды о версии — сборка; окно, журнал, `--version` и проверка берут её оттуда.
- Проверка обновлений не может помешать подсветке: отдельная задача, свои ошибки, ни одного обращения к очереди записи.

**Non-Goals:**
- Скачивание, проверка подписи и установка релиза.
- Хранение времени последней проверки между запусками.

## Decisions

### Версия — `Assembly.GetName().Version`, три числа
`AppVersion.Current` = `typeof(Program).Assembly.GetName().Version` → `Major.Minor.Build`. Это `<Version>` из csproj без хвоста `+sha`, который .NET дописывает к `InformationalVersion`.
- Альтернатива: `Application.ProductVersion` с обрезкой по `+`. Отклонена: та же цифра, но со строковым разбором.

### Запрос — `HttpClient` на задаче пула, раз в 24 часа от запуска
`UpdateCheck.FetchLatest()` — статический `HttpClient` (`Timeout` 15 с, `User-Agent: KbLight/<версия>`, `Accept: application/vnd.github+json`), разбор `tag_name` и `html_url` через `JsonDocument`. Трей запускает его `Task.Run` из таймера WinForms (первый тик 60 с, дальше 24 ч) и результат возвращает в поток окна через `SynchronizationContext.Post` — как и итоги записи.
- Альтернатива: помнить время последней проверки в `settings.json` и проверять «не чаще раза в сутки» между перезапусками. Отклонена: трей обычно живёт от входа до выхода из Windows, так что проверка при входе плюс раз в сутки и есть «раз в день»; лишнее поле и лишние сохранения файла не нужны.
- Без ключа API GitHub даёт 60 запросов в час с одного адреса — с запасом.

### Сравнение — `System.Version` по числам
`tag_name` без ведущей `v` разбирается `Version.TryParse`; нужно ровно три числа. Новее — если `> AppVersion.Current`. Неразборчивый тег — «не новее», без ошибки в журнале: это не сбой сети, а чужой формат тега.

### Где показывается
- Окно: `FlowLayoutPanel` под строкой состояния — серая `Label` «KbLight 1.1.0» и `LinkLabel` «доступна версия <N>», скрытая, пока версии нет. Трей передаёт найденную версию окну при создании и при находке (`SettingsForm.SetUpdate`).
- Уведомление — `NotifyIcon.ShowBalloonTip` (в Windows 11 становится тостом), щелчок — `BalloonTipClicked`. Номер последней показанной версии хранится в поле трея: повторная проверка той же версии молчит.
- Открытие страницы — `Process.Start` с `UseShellExecute = true` на `html_url`; адрес проверяется на префикс `https://github.com/lostintired/sbarda-kblight/`, чтобы из ответа не открылось что-то чужое.

### Флажок и первый запуск
`CheckUpdates` — свойство `LightSettings` (по умолчанию `true`; `System.Text.Json` оставляет значение по умолчанию, если поля нет). Флажок окна поднимает отдельное событие `UpdatesToggled`, как автозапуск, а не `SettingsChanged`: правка сохраняет файл, но не ставит запись в очередь. Пока трей в режиме первого запуска (`_firstRun`), файл не сохраняется — значение остаётся в объекте настроек и попадёт в файл, когда подсветка будет взята из клавиатуры.

### `--version` в оконной программе
Exe собран как `WinExe`, своей консоли у него нет. `--version` вызывает `AttachConsole(ATTACH_PARENT_PROCESS)` и пишет строку в `Console.Out`; если родительской консоли нет (запуск из Проводника), просто выходит с кодом 0. Ни журнала, ни мьютексов, ни сети.
- Альтернатива: окно с версией. Отклонена: ключи командной строки — для скриптов и поддержки, им нужен текст.

## Risks / Trade-offs

- [В PowerShell строка `--version` печатается после приглашения: оболочка не ждёт оконную программу] → в README пример `KbLight.exe --version | Write-Output` (или `cmd /c`), который ждёт; поведение обычное для WinForms-утилит.
- [Брандмауэр или прокси компании блокирует `api.github.com`] → одна строка в журнале до удачи, остальное работает; флажок выключает проверку совсем.
- [Форк с другим репозиторием будет проверять наш] → адрес репозитория — одна константа в `UpdateCheck.cs`, в README для разработчиков сказано, что её менять в форке.
- [Тост Windows не показан из-за «Не беспокоить»] → ссылка в окне остаётся; строка в журнале тоже.

## Migration Plan

Старый `settings.json` без `CheckUpdates` читается как `true`. Версия 1.1.0 читает файл с новым полем, пропуская его, — откат на прежний exe безопасен.

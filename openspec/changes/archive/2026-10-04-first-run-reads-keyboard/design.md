## Context

Сейчас `TrayApp` при старте делает `LightSettings.Load()` и, если файла нет, сразу сохраняет значения по умолчанию (`src/TrayApp.cs`, конструктор), а затем ставит в очередь принудительную запись «запуск программы». `--apply` и `--check` (`Program.ApplyOnce`) тоже пишут значения по умолчанию, если файла нет. Чтение блока (`Keyboard.ReadBlock`) уже есть, но вызывается только внутри `ApplyTo` вместе с записью.

## Goals / Non-Goals

**Goals:**
- Без `settings.json` ни один путь программы не пишет в клавиатуру ничего, кроме выбранного пользователем в окне.
- Подсветку из клавиатуры берёт поток записи трея (очередь `TrayApp`) под мьютексом устройства: поток окна клавиатуру не ждёт.

**Non-Goals:**
- Повреждённый `settings.json` — поведение прежнее (см. «Не входит» в proposal).
- Новые команды или байты протокола.

## Decisions

1. **Признак первого запуска — отсутствие файла, а не флаг в нём.** `TrayApp` запоминает `_firstRun = !LightSettings.Exists` и больше не сохраняет значения по умолчанию в конструкторе. `_firstRun` снимается, когда подсветка взята из клавиатуры или пользователь что-то поправил (`FlushEdits` сохраняет файл). Флаг в JSON не нужен: файла нет — значит, ничего не выбирали.
   Альтернатива — писать файл с пометкой `"FromKeyboard": false` — отвергнута: лишнее поле в формате файла ради состояния, которое и так видно по его отсутствию.

2. **Чтение — режим того же запроса в очереди.** `ApplyRequest` получает поле `Adopt`, равное `_firstRun` в момент запроса. Поток записи для такого запроса вызывает новый `Keyboard.Read()` вместо `Keyboard.Apply`; повторы, паузы и прерывание новым запросом — те же. При слиянии запросов `Adopt` берётся из нового: правка пользователя (`Adopt = false`) отменяет ожидающее чтение.

3. **`Keyboard.Read()`** — те же мьютекс `Local\KbLight.Device`, перебор интерфейсов `MI_01` и сеанс `01 → 05 → 02`, что у записи, без `06`. Общая часть (мьютекс и перебор) выносится из `Apply`, чтобы правила обмена жили в одном месте. Итог — `ApplyResult`:
   - `AlreadySet` с сообщением `первый запуск, взял из клавиатуры: <LightState.Describe>` и блоком — первый исправный блок;
   - `NotFound` — `клавиатура не найдена`;
   - `Failed` — `клавиатура вернула неожиданный блок настроек, настройки не взяты` или текст исключения обмена.
   Статус `AlreadySet` выбран, чтобы подсказка значка, окно и журнал не требовали новой ветки: подсветка в клавиатуре и в настройках совпадает.

4. **Перенос значений — в потоке окна.** `OnApplied` для запроса с `Adopt` и итогом `AlreadySet` проверяет, что `_firstRun` ещё стоит (пользователь не успел поправить), переносит байты 8–16 в общий `_settings` через `LightSettings.SetFromBlock(block)`, сохраняет файл (вместе с `LastGoodBlock`, как сейчас) и обновляет открытое окно (`SettingsForm` получает публичный `Reload()` на основе `LoadValues`). Состояние в подсказке строится из `_settings.Describe()`, а не из снимка запроса: в снимке значения по умолчанию.

5. **Формулы чтения — обратные к `LightState.From`/`WriteTo`:** эффект и номер цвета как есть, яркость `min(b9, 100)`, скорость `clamp(4 − b10, 0, 4)`, направление и разноцветный — `≠ 0`, цвет — `#b14b15b16`. Для значений в допустимом диапазоне следующая запись вернёт те же байты 8–16.

6. **`--apply` и `--check` без файла** — `Program.ApplyOnce` проверяет `LightSettings.Exists` до обращения к клавиатуре, пишет `NoSettings` в журнал и возвращает 3. Строка `NoSettings` — не значение `ApplyStatus`, а только текст журнала: в трее такого исхода нет.

## Risks / Trade-offs

- [Байты 10–16 помечены ◐] → при первом запуске они только читаются, записи нет. Если в клавиатуре лежит значение вне диапазона (например, направление 2), следующая запись после правки заменит его на 1 — как и сейчас при любой записи.
- [Окно, открытое до чтения, показывает «Рябь от нажатий»] → это значения по умолчанию только на экране; после чтения окно обновляется само. Если пользователь успел что-то поправить, приоритет у правки.
- [Эффект 0 или 128 в клавиатуре] → берётся как есть; список «Эффект» в окне остаётся без выбора, как сейчас при незнакомом коде в файле. Запись таких кодов уже разрешена требованием «Перевод в байты клавиатуры».
- [Не удалось сохранить файл после чтения] → строка журнала `настройки не сохранены: …`, значения остаются в памяти, `_firstRun` снимается; при следующем запуске клавиатура будет прочитана снова.

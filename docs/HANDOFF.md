## Можно сразу

От решений не зависит.

1. **Change «первый запуск берёт подсветку клавиатуры».** Сейчас при первом запуске, без `settings.json`, KbLight записывает «Рябь от нажатий» — настройки автора — и затирает подсветку нового пользователя. Затронутые требования: «Значения по умолчанию» в `lighting-settings` и «Запись при запуске» в `auto-apply`. Нужно, чтобы при первом запуске эффект и параметры читались из клавиатуры. У нынешнего пользователя `settings.json` есть, его это не заденет. Сделать `/opsx:propose` и показать proposal пользователю до `/opsx:apply`.
2. **`docs/CHANGELOG.md`.** Пункт «Удалено из системы — битая запись автозапуска sbarda» описывает правку на компьютере автора, а не то, что делает программа. Убрать его; инструкция для других — в README (п. 4 раздела «До публикации»).
3. **Ручная проверка вместе с пользователем** — клавиатура у него; сценарии — в `CLAUDE.md`, «Проверка»:
   - перезагрузка — первая строка журнала `запуск программы: … было: …` покажет, что клавиатура хранит после включения (ADR-006);
   - переподключение кабеля — в журнале `клавиатура подключена: Written — …`;
   - сон — в журнале `выход из сна: …`;
   - в окне поменять скорость, направление (у «Волны»), цвет и разноцветный режим и сверить глазами и по `python tools/kbtool.py read`.

   По итогам поставить пометки ✔ в `docs/PROTOCOL.md` §4–5 и обновить `docs/ARCHITECTURE.md` §13.

## Публикация

Только после явного «публикуем» от пользователя.

1. `git branch -m master main` (решение 1), затем `gh repo create <имя> --public --source . --remote origin --description "<…>"` и `git push -u origin main`.
2. Темы репозитория: `sbarda`, `keyboard`, `rgb-lighting`, `hid`, `windows`, `tray-app`, `dotnet`, `reverse-engineering`.
3. Релиз:
   - `dotnet publish src -c Release -o publish`;
   - SHA256 — `Get-FileHash publish\KbLight.exe`;
   - `gh release create v<версия> publish\KbLight.exe --title "KbLight <версия>" --notes "<из CHANGELOG и SHA256>"`.
4. Проверить страницу: README читается, лицензия определилась, exe скачивается и запускается.

## Живые данные пользователя

- **Клавиатура:** «Рябь от нажатий», яркость 100, скорость 0, разноцветный режим, красный — то же в `%LOCALAPPDATA%\KbLight\settings.json`. После любых опытов вернуть: `"%LOCALAPPDATA%\Programs\KbLight\KbLight.exe" --apply`.
- **Установленный exe** работает в трее и держит файл. Обновлять только по просьбе пользователя, перед этим — «Выход» в меню значка.
- **Задача автозапуска** указывает на установленный exe. Флажок «Запускать при входе в Windows» в любой другой копии (из релиза, из `publish\`) перепишет задачу на эту копию. Проверяя другую сборку, флажок не трогать; если тронули — вернуть: `"%LOCALAPPDATA%\Programs\KbLight\KbLight.exe" --autostart on`.
- **Вторая копия** при работающем трее только откроет окно первой. Чтобы проверить другую сборку, сначала нажать «Выход» у установленной, а после проверки снова её запустить.
- **sbarda.exe** не запускать, кроме исследования протокола; после — закрыть и выполнить `--apply`.

## Готчи среды

- Сессию запускать в `C:\KbLight`: команды `/opsx:*` и скиллы Codex лежат в проекте, в `.claude/` и `.agents/`.
- PowerShell: список через запятую в аргументе CLI брать в кавычки — `--tools "claude,codex"`, иначе выйдет два аргумента.
- `openspec/config.yaml`: пункт правила с «: » YAML читает как словарь, и OpenSpec выбрасывает все правила этого артефакта («must be an array of strings»). Писать через тире или брать в кавычки.
- OpenSpec CLI установлен глобально, версия 1.13.2, вышла 1.14.0; после обновления — `openspec update` в проекте.
- Git:
  - в системном конфиге `core.autocrlf=true`, в репозитории `.gitattributes` с `* text=auto eol=lf`, все файлы в LF;
  - глобальные `user.name` и `user.email` не заданы, они заданы в `.git/config` репозитория.
- Автотестов нет; ворота — сборка без предупреждений и ручные сценарии.
- `tools/kbtool.py` не берёт мьютекс KbLight — не запускать его во время записи из трея.
- Перехват `tools/capture/`: `script.unload()` в Frida зависает, поэтому скрипт выходит через `os._exit`. Перехваченная sbarda.exe остаётся работать — её надо закрыть.
